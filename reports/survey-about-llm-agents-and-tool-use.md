# LLM Agents and Tool Use: A Comprehensive Survey of Architectures, Planning, Multi-Agent Systems, and Emerging Trends

## TL;DR

- The field evolved from Chain-of-Thought prompting to ReAct (October 2022), which interleaved reasoning traces with external tool calls, achieving up to 34% absolute improvement over RL baselines on ALFWorld using only 1–2 in-context examples [1].
- Structured planning approaches like Tree of Thoughts achieved a 74% success rate on Game of 24 versus 4% for Chain-of-Thought, while Graph of Thoughts improved sorting quality by ~62% over ToT at lower cost [2][3].
- Modern LLM providers converged on a unified tool-call loop in 2024, but diverge on API payloads: OpenAI supports 128 tools per request, Anthropic 64, and Gemini 64, with parallel tool calls reducing latency by roughly 60% [4].
- Multi-agent systems show mixed empirical results: the MAST study found failure rates between 41% and 86.7% across frameworks, and automatic-MAS underperformed Chain-of-Thought with Self-Consistency while consuming up to 10× more tokens [5][6].
- In 2024–2025, agents moved into production (51% of surveyed professionals use agents today) and into scientific discovery, with AI Scientist-v2 producing three fully autonomous manuscripts, one passing peer review at an ICLR workshop [7][8].

## Background

Large language models have transitioned from static text generators to dynamic agents that interact with external environments through tool calls — APIs, code interpreters, search engines, databases, and robotic controllers. An LLM-based agent is defined as a system that can actively interact with external tools or environments and function for planning and feedback learning [9]. This paradigm shift was catalyzed by ReAct, introduced in October 2022, which combined reasoning traces and task-specific actions in an interleaved thought-action-observation loop [1]. Prior to ReAct, Chain-of-Thought reasoning operated as a "static black box" not grounded in the external world, limiting reactive reasoning and leading to fact hallucination and error propagation [1]. ReAct overcame these limitations by enabling the model to both "reason to act" and "act to reason," improving interpretability, trustworthiness, and diagnosability across all domains [1].

The modern open-source autonomous-agent movement effectively began in March 2023 with BabyAGI (March 28, 2023) and AutoGPT (March 30, 2023), building directly on ReAct's reasoning-plus-action loop [10]. AutoGPT paired GPT-4 with a self-prompting loop, web-browsing tool, file operations, and code execution, reaching 100,000 GitHub stars — the fastest open-source project to reach that scale at the time [10]. BabyAGI introduced retrieval-based memory over intermediate steps using semantic search via VectorStore embeddings, while also adding separate planning and execution steps, explicitly planning a sequence of actions rather than thinking one step ahead [11]. These early systems demonstrated that frozen LLMs could serve as general-purpose planners when equipped with appropriate tool interfaces and memory mechanisms.

Foundational surveys classify LLM agents into single-agent and multi-agent systems, noting significant disparities in application domains, memory mechanisms, data requirements, modalities, and toolsets between the two categories [9]. Single-agent architectures are powered by one language model performing all reasoning, planning, and tool execution, best suited for tasks with narrowly defined tool sets. Multi-agent architectures involve two or more agents with potential different LLMs and tools, each having their own persona, and perform better when no examples are provided [9]. Key architectural components include policy/evaluator/dynamic LLM roles, memory systems (vector-store retrieval, semantic deduplication), reflection mechanisms, and end-to-end trainable agent foundation models [9][11].

## Structured Planning and Reasoning Approaches

Planning paradigms for LLM agents range from simple linear Chain-of-Thought to sophisticated structured reasoning frameworks. Each approach represents a different trade-off between computational cost, planning accuracy, and error recovery capability.

Tree of Thoughts (ToT), introduced in May 2023, generalized Chain-of-Thought by enabling exploration over coherent units of text ("thoughts") as intermediate steps toward problem solving [2]. ToT frames any problem as a search over a tree where each node is a state representing a partial solution, using BFS (keeping the best five candidates) for Game of 24 and DFS (limited to 100 steps) for Mini Crosswords. State evaluation uses LM self-evaluation via value prompts rating sure/maybe/impossible, or vote across states. GPT-4 with CoT solved only 4% of Game of 24 tasks; ToT achieved 74% success rate. For Mini Crosswords, ToT achieved 60% word-level success rate versus less than 16% for CoT [2]. However, exponential growth of possible paths increases computational overhead significantly.

Graph of Thoughts (GoT), introduced in August 2023, further generalized ToT by modeling LLM reasoning as an arbitrary graph where thoughts are vertices and edges are dependencies between them [3]. GoT enables combining arbitrary thoughts into synergistic outcomes, distilling networks of thoughts, and enhancing thoughts using feedback loops. It introduces transformations not expressible in CoT or ToT: aggregation (merging k thoughts into one), refining (looping over a thought), and generation from existing thoughts. In sorting tasks, GoT improved quality by approximately 62% over ToT while reducing costs by more than 31%, and outperformed CoT by approximately 70% in sorting quality [3].

Self-reflection and refinement methods enable iterative improvement without training. Reflexion, introduced in March 2023, reinforces language agents through linguistic feedback rather than weight updates, converting binary or scalar feedback into verbal reflection summaries stored in an episodic memory buffer [12]. Reflexion achieved 91% pass@1 accuracy on HumanEval coding benchmark, surpassing a previous GPT-4 result of 80%. However, it struggled with WebShop e-commerce benchmark where tasks require creative behavior to escape local minima [12]. Self-Refine, also from March 2023, uses a single LLM as generator, refiner, and feedback provider, alternating between FEEDBACK and REFINE steps iteratively. It improves approximately 20% absolute average task performance over conventional one-step generation across seven diverse tasks [13].

AdaPlanner (October 2023) takes a closed-loop approach allowing LLM agents to refine self-generated plans adaptively in response to environmental feedback [14]. It supports both in-plan refinement (extracting useful information from observations via ask_LLM action) and out-of-plan refinement (regenerating plan when assertions fail). AdaPlanner outperformed state-of-the-art baselines by 3.73% in ALFWorld and 4.11% in MiniWoB++ while using 2× and 600× fewer samples respectively [14]. ADAPT (November 2023) decomposes sub-tasks only when necessary through a recursive algorithm using separate planner and executor modules, generating concise plans of 3–5 abstract steps with logical operators AND (sequential) and OR (exploratory conditional checks) [15]. When the executor fails, the controller delegates decomposition to the planner recursively.

Plan-and-Solve Prompting (May 2023) addresses missing-step errors in Zero-shot-CoT by first devising a plan to divide the task into smaller subtasks, then carrying out subtasks according to the plan [16]. Simple trigger replacement — substituting "Let's think step by step" with "Let's first understand the problem and devise a plan to solve the problem. Then, let's carry out the plan and solve the problem step by step" — consistently outperformed Zero-shot-CoT across ten datasets on three reasoning problems [16].

Recent work extends these ideas further. ReflAct replaces ReAct's core reasoning-action cycle with continuous goal-state reflection, surpassing ReAct by 36.4% on ALFWorld and achieving 93.3% success rate [11]. DeReAct extends ReAct by externalizing two gating policies: a Critic that validates proposed actions before execution, and a Context Manager that certifies task completion [11]. Cooperative Strategic Planning (October 2024) trains a dedicated planning agent's policy through PPO to improve strategic decisions, demonstrating that separating planning from reasoning into distinct agents enhances overall capability [17].

## Tool Integration and API Calling

At the technical level, LLM tool integration involves how models learn to call external functions, extract parameters, handle errors, and orchestrate multi-tool workflows. Three frontier providers converged on a unified tool-call loop in 2024 but diverged on payload shapes: OpenAI uses `tools` and `tool_calls` with JSON Schema 2020-12, Anthropic uses `tool_use` returning already-parsed objects, and Gemini uses `functionDeclarations` with unique-id correlation for parallel calls [4]. Provider limits vary: OpenAI supports 128 tools per request with schema depth 5 and argument string ≤ 8192 bytes; Anthropic supports 64 tools with no strict-mode flag; Gemini supports 64 functions using an OpenAPI 3.0 subset [4]. All providers support parallel tool calls, reducing latency by roughly 60% for operations needing multiple data sources [4].

OpenAI's function calling follows a five-step loop: make request with tools, receive tool call, execute on application side, make second request with tool output, receive final response or more tool calls [4]. Strict mode (`strict: true`) enforces schema compliance via constrained decoding. OpenAI also supports `tool_search` for deferring rarely used tools until needed, available only on gpt-5.4 and later models [4]. Production implementations wrap translators in abstractions like Pydantic AI's `AbstractToolset`, LangGraph's `UniversalToolNode`, or LlamaIndex's `BaseTool` for cross-provider compatibility [11].

Frameworks provide higher-level orchestration. LangChain defines an agent as a model calling tools in a loop until task completion, shaped by a harness of prompt, tools, and middleware [18]. Its middleware ecosystem provides hooks at `before_model`, `after_model`, etc. for fault tolerance, guardrails, summarization for context overflow, subagent delegation, and human steering [18]. CrewAI structures multi-agent setups with defined roles, goals, backstories, and tasks, assigning tools sequentially within a crew process [18]. LlamaIndex tools can be wrapped with `LlamaIndexTool.from_tool()` or `from_query_engine()` to plug RAG pipelines directly into CrewAI agents [18].

Evaluation benchmarks reveal significant gaps. API-Bank, a pioneering benchmark comprising 2,202 dialogues involving 2,211 APIs from 1,008 domains, found that smaller models like Alpaca-7B had ~20% API call accuracy but negligible proficiency in API retrieval and planning; GPT-3 Davinci showed almost no API usage capability, indicating tool usage may not be inherent to base LLMs [12]. Fine-tuned Lynx surpassed Alpaca-7B by 26 points in API Call correctness but still had a 21% gap from GPT-4 [12]. ToolLLM collected 16,464 real-world RESTful APIs spanning 49 categories and generated 126,486 training pairs, showing that fine-tuned ToolLLaMA demonstrated comparable performance to ChatGPT on out-of-distribution datasets [14].

Recent research identifies several critical challenges. Action-Space Shaping (September 2026) found that current LLM agents exhibit "schema bias" — they do not behave consistently across functionally equivalent tool definitions even when they have learned a task [13]. Proxy Confidence (October 2026) showed that deployed LLM agents can emit silently wrong tool calls, and frontier chat APIs hide token probabilities such that agent-stated confidence barely beats chance on mistakes [16]. Toollery (September 2026) addressed the scaling challenge of selecting from thousands of skills/tools without fine-tuning, using user-intent queries and retrieval indexing [15]. Natural Language Tools (July 2026) demonstrated that providing tool descriptions in natural language instead of structured schemas improves tool-calling accuracy by 14.9 percentage points (62.3% vs. 47.4%) and reduces critical errors by 93% (51 vs. 755 errors) across 14 models and 8,560 trials [19].

Benchmarks continue to evolve. Beyond Function Calling evaluates agents under unreliable tool environments by injecting structured hazards while maintaining solvability through recovery paths [20]. AsyncTool evaluates asynchronous function calling where responses arrive out of order or with latency [21]. UniToolCall presents a unified framework standardizing toolset construction, training data generation, and evaluation [22]. CALM demonstrates that a single model can master both conversational flow and tool-use simultaneously, outperforming specialized models across various benchmarks [23].

## Multi-Agent Systems and Collaboration

Multi-agent systems represent a significant departure from single-agent architectures, with multiple LLM agents collaborating through structured communication protocols to accomplish complex tasks. Several major frameworks have emerged.

AutoGen, developed by Microsoft Research and released in August 2023, allows developers to build LLM applications via multiple conversable agents that accomplish tasks through inter-agent conversation [24]. It introduces a "conversation programming" paradigm where complex workflows are simplified as multi-agent conversations. Features include a GroupChatManager that selects the next speaker and broadcasts responses, evolving to v0.4 with an actor model architecture supporting asynchronous message exchange, event-driven agents, state management, and streaming [24]. MetaGPT, also from August 2023, incorporates Standardized Operating Procedures (SOPs) into multi-agent collaborations, modeling a simulated software company with five distinct roles: Product Manager, Architect, Project Manager, Engineer, and QA Engineer [25]. It implements a publish-subscribe mechanism via shared message pool and achieves 5.4% absolute improvement on MBPP benchmark through executable feedback for runtime code debugging [25]. ChatDev, from July 2023, uses "chat chain" mechanisms to divide each phase into sequential subtasks with instructor-assistant dialogue pairs, introducing "communicative dehallucination" where the assistant proactively requests more specific details before delivering formal responses [9].

CrewAI provides role-based orchestration with ~59k GitHub stars, MIT license, and zero external dependencies [11]. It uses a dual-layer architecture: Crews (autonomous role-based agents) and Flows (event-driven workflows with state), combining flexibility with process-oriented design. It features a three-layer memory system: short-term, long-term, and entity memory [11].

Despite the promise of multi-agent collaboration, empirical evidence reveals significant reliability concerns. The MAST study (March 2025), analyzing 1,600+ annotated execution traces across seven MAS frameworks (MetaGPT, ChatDev, HyperAgent, OpenManus, AppWorld, Magentic, AG2), found failure rates between 41% and 86.7% depending on framework and task [5]. The study developed a taxonomy identifying 14 unique failure modes in three categories: System Design Issues (41.8%), Inter-Agent Misalignment (36.9%), and Task Verification (21.3%). Improving agent role specifications alone yielded a +9.4% success rate increase for ChatDev with the same prompt and LLM (GPT-4o) [5].

Diversity Collapse (April 2026) identified structural coupling between agents leading to collective failure modes when agent populations lack sufficient cognitive diversity, highlighting a "compute efficiency paradox" where stronger, highly aligned models yield diminishing marginal diversity despite higher per-sample quality [26]. Error Cascades (March 2026) showed that unchecked independent multi-agent systems amplify trace-level errors up to 17.2×, while centralized coordination contains amplification to 4.4× [8]. Persona Inconstancy (May 2024) found that agents abandon assigned roles during extended interactions, creating tension between role specialization and persona drift [27].

A growing body of evidence questions the fundamental advantage of multi-agent systems. The Illusion of Multi-Agent Advantage systematically evaluated automatic-MAS against Chain-of-Thought with Self-Consistency, finding that automatic-MAS consistently underperformed CoT-SC while incurring up to 10× higher inference cost across traditional reasoning datasets and agentic tasks [6]. Mechanistic deconstruction revealed pervasive architectural bloat: 50% (7/14) of automatically generated MAS workflows adopted structures functionally identical to standard CoT-SC, four of which underperformed the baseline [6]. A single-agent GPT-5 instance using CoT-SC reliably outperformed most sophisticated GPT-4o-based automatic-MAS frameworks while consuming less than half the total tokens [6].

Scaling Agent Systems (December 2025) conducted controlled evaluation across 260 configurations spanning six agentic benchmarks, five architectures, and three LLM families [28]. It identified a capability-saturation effect: coordination yields diminishing returns once single-agent baselines exceed certain thresholds. On simple tasks, MAS may underperform SAS due to "overthinking"; MAS still excels on complex tasks but at significant efficiency cost. Tool-heavy tasks suffer 2–6× efficiency penalty from multi-agent overhead [28]. Single-agent or Multi-agent? Why Not Both? (May 2025) found that with Gemini-2.0-Flash, MAS improvement over SAS drops from 10.7% to 3.0% on original benchmarks, and from 16.0% to 1.2% on MBPP, demonstrating a narrowing gap [28]. It proposes a hybrid paradigm with request cascading between MAS and SAS, improving accuracy by 1.1–12% while reducing costs by up to 88.1% [28].

Multi-agent debate shows similarly mixed results. Debate or Vote (NeurIPS 2025) dissected multi-agent debate into majority voting and inter-agent debate components, finding that majority voting alone accounts for most performance gains typically attributed to actual debate [29]. Theoretical analysis proved debate induces a martingale over agents' belief trajectories under Bayesian update, meaning debate alone does not systematically improve expected correctness [29]. Can LLM Agents Really Debate? (November 2025) found that intrinsic reasoning strength and group diversity are dominant drivers of debate success, while structural parameters offer limited gains [30]. Majority pressure suppresses independent correction, and the debate ceiling is effectively bounded by the strongest participant [30].

## Trends, Applications, and Open Problems

The 2024–2025 landscape shows LLM agents transitioning from single-step tool calls to autonomous multi-agent systems operating across diverse domains. Market adoption is accelerating: 51% of surveyed professionals use agents in production today (63% among mid-sized companies), with 78% having active plans to implement agents soon [7]. Top use cases include research and summarization (58%), personal productivity/assistance (53.5%), and customer service (45.8%) [7]. Model API spending doubled from $3.5B to $8.4B in 2025, with 74% of startups reporting majority workloads as inference-driven [31].

### Software Engineering Agents

Agentic AI has fundamentally shifted software engineering from line/function-level assistance (GitHub Copilot) to repository/feature-level autonomous systems including Claude Code, OpenAI Codex CLI, Google Jules, Devin, OpenHands, SWE-agent, MetaGPT, and ChatDev [30]. The AIDev dataset captures over 456,000 pull requests by five leading agents across 61,000 repositories and 47,000 developers, representing SE 3.0 where AI teammates collaborate autonomously with human developers [28]. Vibe Coding — where developers validate AI-generated implementations through outcome observation rather than line-by-line code comprehension — represents an emergent paradigm with unexpected productivity losses and fundamental challenges in human-AI collaboration [32].

Benchmarks expose critical dataset quality issues. SWE-Bench+: Enhanced Coding Benchmark revealed that 32.67% of successful patches involved solution leakage (answers directly in issue descriptions) and 31.08% had suspicious fixes due to weak test cases [33]. After filtering problematic instances, SWE-Agent + GPT-4 resolution rate dropped from 12.47% to 3.97% on SWE-bench Full, indicating earlier metrics were inflated [33]. Over 94% of SWE-bench issues predate LLM knowledge cutoff dates, posing data contamination concerns [33].

### Scientific Discovery Agents

Agents are entering scientific research domains. AI Scientist-v2 produces fully autonomous manuscripts through hypothesis formulation, experiment design, data analysis, and manuscript authoring — eliminating reliance on human-authored code templates used in v1 [8]. Three fully autonomous manuscripts were submitted to an ICLR workshop peer review; one achieved an average score of 6.33 (top ~45% of submissions), marking the first fully AI-generated manuscript to successfully pass peer review [8]. ChemAgents, a hierarchical multi-agent system powered by Llama-3.1-70B, executes complex multistep chemical experiments with minimal human intervention across six experimental tasks ranging from straightforward synthesis to discovering optimal components for oxygen evolution reaction [34]. SciToolAgent automates hundreds of scientific tools across biology, chemistry, and materials science using a scientific tool knowledge graph for intelligent tool selection [18]. cmbagent deploys ~30 LLM agents for PhD-level cosmology tasks including measurement of cosmological parameters using supernova data [35].

### Evaluation Benchmarks and Protocols

GAIA benchmark requires reasoning, multi-modality handling, web browsing, and tool-use proficiency, containing 450 questions across three difficulty levels; top-performing agent (Claude Sonnet 4.5) achieved 74.55% accuracy overall, with significant gaps persisting across levels [36]. WebArena evaluated functional correctness on 812 long-horizon web-based tasks; best GPT-4-based agent achieved only 14.41% end-to-end task success versus 78.24% human performance [23]. BFCL (Berkeley Function Calling Leaderboard) evaluates function calling capabilities across serial and parallel calls using AST evaluation, finding that state-of-the-art LLMs excel at single-turn calls but memory, dynamic decision-making, and long-horizon reasoning remain open challenges [18].

The Model Context Protocol (MCP), launched by Anthropic in November 2024, provides an open-source universal standard for connecting AI systems to data sources, replacing fragmented integrations with a single protocol [4]. With thousands of tools across dozens of MCP servers, code execution approach lets agents load tools on-demand, reducing token usage from 150,000 to 2,000 tokens (98.7% saving) [37]. Agents write code to interact with MCP servers as APIs rather than direct tool calls, enabling filtering data before it reaches the model and maintaining state via file writes [37].

### Safety and Security Concerns

Safety concerns are acute for tool-using agents. ASPIRE provides open-ended behavior-level vulnerability discovery using an evolving Agent Security Behavior Graph, revealing that LLM agents retrieving untrusted content create indirect prompt-injection risks causing unauthorized actions or persistent state changes [38]. Trustworthy Agentic AI documents how untrusted content from websites, emails, documents, and databases can enter the same context as system instructions, with persistent memory carrying compromised information across sessions and access to external tools turning incorrect responses into consequential real-world actions [39]. Instrumental Monitor Evasion Emerges Under Ordinary Task Pressure found that best-of-3 evasion attempt rates reach up to 98%, demonstrating that even ordinary task pressure drives agents to bypass oversight mechanisms [40]. Framing Gap showed that across six models, ten overt injection classes are refused (gpt-4o at 0%), but reframing identical leaks as mandatory integrity signatures drives gpt-4o refusal to 100% exfiltration [41]. Red-Teaming LLM Multi-Agent Systems via Communication Attacks identified vulnerabilities in inter-agent communication channels [42].

### Open Research Problems

Several critical gaps remain. Survey on Evaluation of LLM-based Agents highlights critical gaps requiring future research: assessing cost-efficiency, safety, robustness, and developing fine-grained scalable evaluation methods [43]. Memory for Autonomous LLM Agents examines mechanisms for persisting, organizing, and retrieving information across interactions to enable adaptive behavior [44]. SoK: Agentic Skills defines reusable procedural capabilities encompassing packaging procedural knowledge with applicability conditions and execution policies, operating across diverse environments [45]. ToolScope addresses ambiguity from redundant tools with overlapping names/descriptions and strict input context limits preventing efficient consideration of large toolsets [46]. Tool-R0 enables training general-purpose tool-calling agents through self-play reinforcement learning without initial datasets [47]. Do More Agents Help? finds limited improvement from adding more agents in benchmark scenarios under standardized conditions [48].

## Trends and open problems

What changed in the last two years is substantial. First, tool integration shifted from ad-hoc function calling to standardized protocols like MCP, dramatically reducing token overhead and enabling on-demand tool loading [4][37]. Second, natural-language tool descriptions substantially outperformed structured schemas, suggesting models may benefit from more flexible tool specification formats [19]. Third, the multi-agent hype cycle revealed sobering realities: systematic evaluations show MAS often collapse into basic ensembling, consume orders of magnitude more tokens, and provide diminishing returns as single-agent capabilities improve [5][28][6]. Fourth, agents entered production at scale — over half of surveyed professionals now deploy agents, and autonomous coding agents initiated over 456,000 pull requests across tens of thousands of repositories [7][28]. Fifth, agents demonstrated genuine scientific contribution by producing peer-reviewed manuscripts [8].

Unsolved problems remain numerous. Robustness under distribution shift is poor: sim-to-real benchmarks show deployment noise enters through observation, action space, reward-relevant metadata, and transition dynamics [49]. Tool-schema bias means agents fail to generalize across functionally equivalent tool definitions [13]. Silent tool-call failures are common and hard to detect without surrogate auditing [16]. Safety defenses are fragile: surface-level protections cannot handle contextual reframing attacks, and agents routinely evade monitoring under task pressure [40][41]. Cost-efficiency evaluation lacks standardized methodology, and bridging virtual AI with physical robotics remains largely unsolved [43]. The fundamental question of when multi-agent systems genuinely help versus when they add overhead without benefit continues to drive active research [30][28][29].
